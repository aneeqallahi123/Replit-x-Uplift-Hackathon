# Dastak Voice Agent — Complete Architecture Reset

## What was built before and why it is wrong

The previous implementation built a SIDEBAR that opens alongside the 
website and fills a form inside itself. This is the opposite of what 
is needed.

DELETE voice-agent.js entirely and start fresh. The concept must be 
rebuilt from scratch with the correct mental model.

---

## The correct mental model (read this carefully before writing code)

Think of a real person sitting next to a confused citizen, helping 
them use a website. The helper does not open a separate window and 
do things there. The helper points at things on the ACTUAL website 
and says "click here", "now scroll down", "now click that card", 
"now type your name in this box".

That is exactly what this agent does.

The agent is an INVISIBLE LAYER that floats on top of the real 
website. It:
  - Shows a floating pointer/cursor that moves around the screen
  - Points at real elements on the real website
  - Clicks real buttons that trigger real website behavior
  - The website responds naturally to those clicks (offcanvases open,
    pages navigate, modals fire) exactly as they would if a human 
    clicked them
  - The agent then moves to the next element and continues

The agent never opens its own form. It never has its own sidebar. 
It never fills anything in a container it created. It only 
interacts with elements that already exist in the website's own HTML.

When the agent clicks the "Renewal of Regular License" card, the 
WEBSITE'S OWN offcanvas opens (because that is what the website 
does when you click that card). The agent then moves its pointer 
into that offcanvas and fills the WEBSITE'S OWN form fields.

The agent is a ghost operating the real website. It does not 
build its own website alongside it.

---

## What the agent looks like visually

Two things float on screen at all times, injected by voice-agent.js:

1. A green circular pointer (44px, border: 3px solid #167B38)
   This is the "finger" that points at and clicks things.
   It moves with smooth CSS transitions.
   It pulses when it clicks something.
   It is the ONLY thing the agent adds to the visual experience.

2. A floating panel in the bottom-right corner containing:
   - A status bubble (shows Urdu text about what the agent is doing)
   - A mic button (green circle, 60px)
   
   This panel is SMALL and UNOBTRUSIVE. It sits in the corner.
   It does NOT take up half the screen.
   It does NOT contain a form.
   It does NOT contain any navigation of its own.

That is the entire visual footprint of the agent. Everything else 
the user sees is the real Dastak website responding to real clicks.

## Required fix: services.js wizard validation

The existing services.js likely validates Step 1 before allowing 
the Next button to advance the wizard. When the agent fills fields 
programmatically, Bootstrap validation may not recognise the values 
as "filled" because no real keyboard events were fired.

To fix this, the typeIntoField function must fire the correct events:

  el.value += char;
  el.dispatchEvent(new Event('input',  { bubbles: true }));
  el.dispatchEvent(new Event('change', { bubbles: true }));
  el.dispatchEvent(new KeyboardEvent('keyup', { bubbles: true }));

After filling ALL fields in a step, before clicking Next, 
also trigger blur on each field:
  el.dispatchEvent(new Event('blur', { bubbles: true }));

If the Next button click still does not advance the wizard 
(because validation blocks it), add this safety fallback 
immediately after the click:

  // Safety fallback: if wizard did not advance, force it
  const step1 = document.getElementById('step1-content');
  if (step1 && step1.style.display !== 'none') {
    // Step 1 is still showing — validation blocked Next
    // Manually hide step 1 and show step 2
    step1.style.display = 'none';
    const step2 = document.getElementById('step2-content');
    if (step2) step2.style.display = 'block';
    // Update stepper visuals
    document.querySelector('[data-step="1"]')
      ?.classList.remove('active');
    document.querySelector('[data-step="2"]')
      ?.classList.add('active');
  }

## Three-layer architecture (keep this separation clean)

### Layer 1 — Pointer Engine (pure DOM interaction, no Dastak knowledge)

  delay(ms) → Promise

  setStatus(text, show = true)
    Sets #mic-status-bubble text. show=false hides the bubble.

  async movePointerTo(el)
    1. Guard: if (!el) { console.warn('element not found'); return; }
    2. Check if el is in viewport. If not, scroll it into view:
         el.scrollIntoView({ behavior: 'smooth', block: 'center' })
         await delay(500)
    3. Get fresh getBoundingClientRect() AFTER scroll
    4. Center pointer on element (x - 22, y - 22)
    5. Add .active to pointer
    6. await delay(500) for CSS transition

  triggerPulse()
    Remove .pulse, force reflow, add .pulse back

  async hoverElement(el, ms)
    await movePointerTo(el)
    await delay(ms)

  async clickElement(el)
    await hoverElement(el, 400)
    triggerPulse()
    await delay(200)
    el.click()
    await delay(300)

  async typeIntoField(el, value)
    await movePointerTo(el)
    triggerPulse()
    el.classList.add('field-highlight')
    el.value = ''
    for (const char of value) {
      el.value += char
      el.dispatchEvent(new Event('input',  { bubbles: true }))
      el.dispatchEvent(new Event('change', { bubbles: true }))
      el.dispatchEvent(new KeyboardEvent('keyup', { bubbles: true }))
      await delay(60)
    }
    el.dispatchEvent(new Event('blur', { bubbles: true }))
    await delay(300)
    el.classList.remove('field-highlight')

  hidePointer()
    pointer.classList.remove('active')

### Layer 2 — Navigation Actions (Dastak-specific, calls Layer 1 only)

  These are the individual named steps described in the flow above.
  Each function does exactly one thing.
  None of them touch the DOM directly — they call Layer 1 functions.

  async navClickApplyService()
  async navScrollToDlims()
  async navClickDlimsCard()
  async navClickRenewalCard()
  async navWaitForOffcanvas()
  async navFillFullName(value)
  async navFillCnic(value)
  async navClickNext(statusText)
  async navSkipDocuments()
  async navCheckTerms()
  async navSubmit()

### Layer 3 — Orchestrators (page-specific flows, calls Layer 2 only)

  async runHomePageFlow()
    Runs STAGE 1 (index.html steps)
    Calls navClickApplyService → navScrollToDlims → navClickDlimsCard
    After navClickDlimsCard, window navigates to services.html
    The services page will auto-start runServicesPageFlow() 
    if it detects a URL param: services.html?autostart=true
    So navClickDlimsCard should navigate to 
    "services.html?autostart=true" not just "services.html"

  async runServicesPageFlow()
    Runs STAGES 2-6 (services.html steps)
    Called either by mic button click on services.html,
    OR automatically on page load if URL contains ?autostart=true:
    
      window.addEventListener('DOMContentLoaded', () => {
        if (window.location.search.includes('autostart=true')) {
          setTimeout(() => runServicesPageFlow(), 800)
          // 800ms delay lets the page fully render first
        }
      })

  After consent → start runServicesPageFlow()

  Page load → auto-start runServicesPageFlow() after 800ms
  No mic click needed — flow continues from where home page left off
